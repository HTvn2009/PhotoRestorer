Guide

Help

Detailed guide for restoring, describing, saving, sharing, and preparing showcase projects.

Add an image name, write any context you already know, upload a JPG, PNG, or WEBP image, then choose Run restoration. PicRes previews the source photo, sends it to the server, restores and colorizes it, then shows the result in the AI output panel. Choose Run restoration again to process the same upload another time if the result needs another attempt.

Use real photos of people, family memories, buildings, landmarks, cultural objects, documents, artifacts, ceremonies, or historical scenes. Files must be JPG, PNG, or WEBP and under 10 MB. Clear images work best, but faded, scratched, blurry, or damaged photos can still be restored. Avoid screenshots, cartoons, AI-generated images, heavily edited pictures, or photos where the important subject is too small to inspect.

The restoration workflow preserves the original subject, composition, faces, clothing, architecture, artifacts, text, and cultural or historical context. It repairs visible damage, reduces dust and scratches, improves clarity, balances exposure and contrast, and produces a naturally colorized PNG. It should not invent missing people, objects, symbols, writing, landmarks, or historical details.

Write only facts you already know, such as a person, place, date, event, object name, collection note, or family story connected to the photo. If you are unsure, leave the context field blank or use cautious wording. The AI description uses visible evidence and your supplied context, so unsupported claims should be reviewed before saving or sharing.

Run description to classify the image and generate structured notes such as subject, origin, period, purpose, significance, historical or cultural context, observed details, warnings, and whether human verification is recommended. For uncertain artifacts, landmarks, dates, origins, or identities, treat the output as a draft that needs documentation or expert review.

After a restoration is ready, Save stores the project in your browser's local gallery with the name, original image, restored image, description, and saved date. In My Gallery you can open a project, compare Before and After, favorite it, filter favorites, rename it, delete it, or create a share link. Gallery data is stored locally in the browser unless you choose to share.

Share creates a link for a saved project and copies it to the clipboard. A shared project includes the saved name, description, before image, after image, and date. On the local Node server, shared projects are kept in memory, so links may stop working when the server restarts. On deployed serverless routes, persistence depends on the hosting environment.

Showcase displays prepared restoration projects that are written directly in the source code. Visitors can view the before image, after image, name, and description, but there is no web UI for editing them. To add, remove, or modify Showcase projects, edit the showcaseProjects array in public/app.js and place image files in public/showcase/.

AI restoration and description require OPENAI_API_KEY on the server. The key is never placed in frontend JavaScript. Uploaded images are sent to the backend only when you run restoration or description, and they are not added to My Gallery unless you choose Save. If OPENAI_API_KEY is missing, the app will show a server configuration error.
